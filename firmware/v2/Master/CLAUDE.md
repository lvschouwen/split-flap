# v2 Master (ESP32-S3)

Loaded when working in this tree; root CLAUDE.md holds build commands, workflow and Hard rules. One line per mechanism: what it is + issue # + the file(s) whose headers carry the detail. Specs in `docs/superpowers/specs/`.

## Mechanisms

- **Tasks (#187):** dual-core FreeRTOS — display domain core 1, network core 0; command queue in, mutex-copied snapshots out. Contract in `Tasks.h`; TU family (#352): `Tasks.cpp` (IPC + lifecycle + core-0 wrappers), `DisplayTask.cpp` (core-1 display domain, per-opcode exec* helpers), `ClockTask.cpp` (1 Hz ticker), seams in `TasksInternal.h` (family-only include). PSRAM-preferred buffers via `LargeAlloc.h`.
- **Settings (#185):** NVS (`splitflap` namespace) behind the `SettingsStore` seam — policy in `Settings.h` (natively tested), `NvsSettingsStore.h` is target-only glue.
- **Web (#186/#338):** `web/` + `data/` + `build_assets.py` PROGMEM bake on `esp32async/ESPAsyncWebServer`. TU family: `WebEndpoints.cpp` = shared state + init/loop core (async-context rules in its header; drain order in `webEndpointsLoop` is load-bearing), route handlers in `WebContent`/`WebSettings`/`WebSystem`/`WebFirmware`/`WebWall`/`WebBoard`/`WebStream`.cpp, internals via `WebEndpointsInternal.h` (include from Web*.cpp ONLY). `GET /api` lists every route (`ApiIndex.h`); `tests/test_api_index.py` holds the index to the routes served and keeps the routes `/api/v2` replaced from coming back. Outside `/api/v2`: the page at `/`, `GET /settings` (what the board is and runs; the flashing tools read it), the WiFi portal, the firmware uploads, `/debug/ota`, `/coredump/*`, `/units/odometer-log`, `/health`. `WebAssets.h` is included by `WebContent.cpp` ONLY (a second include duplicates every PROGMEM blob). IANA tz table baked from `data/zones.csv` → `GET /tz.json`.
- **WiFi (#188):** pure `WifiPolicy.h` join/portal/reboot state machine run by `WifiService.cpp` from netTask; credentials in our NVS, `WiFi.persistent(false)` everywhere. A join window that closes without a link is retried by rebooting — `WIFI_JOIN_ATTEMPTS` (3) boots in a row before the portal opens (#524); the tally is an `RTC_NOINIT` record (survives a software reset, not a power cycle), cleared on going online and on opening the portal, and each retry's reboot cause carries the last STA disconnect reason. `tests/test_wifi_join_retry_glue.py` pins the glue.
- **WiFi TX power ladder (#506/#507):** pure `shared/WifiTxPolicy.h` (also run by the ESP-01 follower, #508) — every boot starts at the lowest real IDF level (2 dBm) and moves ONE level at a time (join ceiling 8.5 dBm, online ceiling 13 dBm, up-steps wait for idle units, nothing persisted). Steps follow evidence of need (#515): a dropped link earns a level up to the online ceiling; a weak signal estimate counts only while no exchange with a row board is being confirmed (`wifiNoteConfirmedTraffic()` — a message read on the wall link) and never past the join ceiling. Each step line logs its reason, the received signal and the estimate; the join line logs the access point. Applied by `WifiService.cpp`, `txPower` in the board's `stats`. Never restore the SDK default — full TX power on the shared 5 V rail is what crashed the master.
- **OTA (#190/#305):** `POST /firmware/master` with mandatory `?md5=` onto the inactive A/B slot; images boot `PENDING_VERIFY`, confirmed **pre-inrush at the end of `setup()`** (netif-up is a fallback bar only — a later confirm loses to the boot-inrush brownout). Detail in `OtaService.h`/`.cpp` + `OtaStatus.h`.
- **Clock/NTP (#192):** `configTzTime` at boot/join/tz-POST (`ClockService.h`); pure `ClockPolicy.h` ticked 1 Hz on core 1 — one command per minute, gated on NTP sync.
- **Status LED (#199):** WS2812 on GPIO 48, pure `StatusLedPolicy.h`, ticked from netTask. Boot banner with partition diagnostics owned by `main.cpp`.
- **Flash log (#206):** LittleFS tee of the serial/web-log stream on the `storage` partition, read by `GET /api/v2/log?kind=flash` — `FlashLog.h` + `FlashLogPolicy.h`; writer discipline in root Hard rules.
- **Slot confirm records (#200):** per-slot NVS record stamped on first netif-up so Rescue can rank images (the app-descriptor stamp freezes at framework-assembly time under pioarduino). `SlotRecord.h` ↔ parse-only copy `RescueSlotRecord.h`.
- **I2C unit bus (#203):** `UnitBus.cpp`/`.h` (sole Wire toucher — root Hard rules), blocking transactions at 100 kHz (#375's 400 kHz reverted by #383 — twiboot reflash + wall signal integrity); pure seams `FlapFrame.h`, `UnitHealth.h`, `UnitProtocolHelpers.h`, `RenderStagger.h` (#324: bulk render pauses between unit groups so a full row's flap inrush doesn't brown out the rail — the runtime twin of the #309 boot-home stagger; copied to FollowerEsp01). Per-unit I2C error attribution (#367): failed render-writes + heartbeat-reads charged to their address via file-static counters, folded into `UnitFacts` (`err`/`errAge` in the unit facts) — the instrument any future bus-speed raise is validated against; the global `busErrCount` (#245) stays.
- **Calibration + provisioning (#204):** every op is a DisplayCommand with a seq, started as a job (`POST /api/v2/action`) and read back from the display snapshot's result slots; validation + result vocabulary pure in `shared/MaintenancePolicy.h`, re-run by displayTask pre-burn; op grading via `maintGrade*`, the self-test wait in `shared/SelfTestPoll.h` and the in-system twiboot update in `shared/BootUpdateOp.h` (displayTask supplies `BootUpdateHooks`) — the ESP-01 row runs the same three; op/abort contracts in `UnitBus.h`; probe-inhibit in `DisplayTask.cpp`.
- **Unit bus protocol (#534):** `UnitBus.cpp` is the Wire adapter (`WireTwibootBus`: counted transmissions, crash breadcrumbs, the #207 bus rebuild in `readFailed()`), the S3-only bus checks (canary, phantom-ACK) and the frame/motion orchestration. Every frame, read + validation, verified write, the probe/poll reads and the per-unit error ledger are `shared/UnitBusCore.h`; the rescue probe, boot-section read and unit flash `shared/UnitBusTwiboot.h`; the boot dump `shared/BootDumpOp.h`. The ESP-01 row runs the same headers; `tests/test_shared_logic.py` forbids a unit opcode, reply validator or payload encoder in a tree.
- **Unit reflash over twiboot (#205):** bundled unit hex (`data/unit-firmware.hex` + `.rev`; staged by `make_manifest.py`, CI drift-gated) flashed by `runReflashJob` in `DisplayTask.cpp` through the shared loop `reflashRunTargets` (batch throttle + #412 halt). The job is the whole unit update — idle wait, flash, one home, boot-section sweep (`shared/UnitUpdateJob.h`); the `update-units` job's `force` reflashes one addressed unit. Bootloader identity, fuse/lock and crash-held units: `shared/TwibootProtocol.h`, `UnitRescuePolicy.h` (#541–#543); plan + progress pure in `shared/ReflashPlan.h` (batch size = `REFLASH_BATCH_SIZE` build flag); producer gate in root Hard rules. The twiboot wire client is `shared/TwibootFlash.h` (#526), templated on a bus adapter — `UnitBus.cpp` supplies `WireTwibootBus` (its `readFailed()` is the #207 bus rebuild) and keeps only the orchestration. The follower runs the same header; `tests/test_twiboot_shared.py` forbids framing a twiboot command anywhere else and pins the guard order of both flash paths.
- **Wall in Home Assistant (#566/#570):** `units_faulty` counts the units whose verdict is a fault, on every board (`wallFaultCounts()` in `WallWatch.cpp`). With row boards, a `wall_problem` sensor (on while any board's verdict is a fault, the own row included; the boards with their verdicts as attributes), text/state = the whole wall, width = every board's units — pure `WallMqtt.h`, published every 5 s by `MqttService.cpp`, which also blanks the retained configs of the two sensors the old cluster had.
- **MQTT + Home Assistant (#224):** 24 discovery entities (incl. #366 fleet-min supply-Vcc voltage sensor), LWT, five command topics on espMqttClient, owned by mqttTask — `MqttService.h`/`.cpp`, pure logic in `MqttHelpers.h` + `MqttLifecyclePolicy.h`; spec `2026-07-12-v2-mqtt-ha-slice.md`.
- **Transient/mode service (#219):** a text shown for a time rides the MQTT show-then-revert overlay — drain and producer gates in `WebEndpoints.cpp`, overlay lifecycle (broker-less capable, cross-task arm via `mqttStartNotificationDwell`) in `MqttService.cpp`.
- **Boot-section integrity watch (#520):** every health poll and probe also reads the unit's `GET_BOOT_INFO` report and judges it against `BOOT_CURRENT_CRC32` (pure `shared/BootIntegrity.h`; glue `refreshUnitBootVerdict` in `UnitBus.cpp`, same in `FollowerBus.cpp`) → `bv`/`bcrc` in the unit facts; a bootloader matching no known image counts as faulty and logs once per change. The unit recomputes its report every 10 min while parked, so the verdict is current, not boot-time. Detection only — repair is the boot-update op. `tests/test_boot_integrity_glue.py` pins the call sites.
- **Unit wear odometer (#231):** per-unit revolution count read at probe/health-poll (checksummed 5-byte reply — pre-odometer unit fw fails it gracefully); relative-wear flagging pure in `WearPolicy.h` → the unit verdict's `worn` note + HA wear sensor; reset is the `reset-odometer` job.
- **Board vitals (#245/#251):** netTask samples S3 vitals dual-rate (1 s now, 5 s history ring) — `SystemStatsPolicy.h` pure + `SystemStats.cpp` glue; `stats` in `GET /api/v2/board/<master>`; I2C tx/err counters in `UnitBus.cpp` (sketch-protocol traffic only — idle polls and twiboot excluded).
- **Unit-health event log (#322/#366):** per-unit health that was JSON-only now also logs to the flash/web stream on TRANSITION — drift auto re-home (de counter delta, pure `DriftLogPolicy.h`, emitted in `refreshUnitDiag`) and home-failed/hall-never/stale/mismatch/low-Vcc onset+recovery (pure edge logic `UnitEventLog.h`, emitted per-unit in `heartbeatTick` where each signal is coherent). #366 low-Vcc: since-boot `vccMin` (#306) below a fixed `UNIT_VCC_MIN_FLOOR_MV` (4000 mV, TODO NVS) logs once as a brownout precursor — onset-only (a since-boot minimum can't recover). Baselines live in `UnitFacts` (per probe epoch, survive transient read gaps). The unit's own drift re-home is otherwise silent (prints only to the Nano's unmonitored serial).
- **Unit-count override / dummy mode (#289):** NVS `unitCount` (0 = auto) pins `displayWidth` over the probe result at every `displayApplyUnitFacts` fold (atomic knob in `Tasks.cpp`, folds in `DisplayTask.cpp`); probe/health/counts stay bus truth. `unitCountOverride` in `/settings`.
- **Boot guard (#281):** crashes in a row (panic, any watchdog reset or a CPU lockup; a brownout and a restart on purpose neither count nor forgive) are counted in an `RTC_NOINIT` record — pure `BootGuardPolicy.h`, glue `BootGuard.cpp`. At 3, `bootGuardBoot()` at the top of `setup()` erases otadata and restarts into the rescue image, only when the whole factory image verifies (`factorySlotImageVerified()`); otherwise the board stays on its image. 60 s of running netTask or a power-on forgives the count. Trips (how many, the last reset reason and rev) are kept in NVS `sfboot`; `bootGuard` in `/settings`, `guard` in the board's facts. `tests/test_boot_guard_glue.py` pins the glue.
- **Watchdogs (#314/#328):** 30 s TWDT, all app tasks subscribe + FEED-INSIDE long ops (never unsubscribe) — `TaskWatchdog.h`; WiFi reconnect watchdog pure in `WifiPolicy.h`.

Partition table `partitions_splitflap_16MB.csv` is immutable over OTA. `board_upload.arduino.boot_app0` must equal the CSV's otadata offset (0x19000); layout + factory-reset invariants pinned by `tests/test_partition_table.py`.

## Wall link (#559, master side #566)

- **Link task:** listens on port 7411 for the ESP-01 row boards, one TCP connection per row, opened by the row (`WallLink.cpp`, sole toucher of those sockets; lwIP `select`, state in PSRAM). What a connection means is pure `WallLinkCore.h` (who is behind it, one per row, the paired address wins a row's place, latest text only, ping only when idle, never to a busy row) on the timing rules of `WallLinkPolicy.h`. Messages: `../link/wall_link.proto`.
- **Rows table:** `WallRows.h` — the boards of this Split-Flap with their grid place (`id|host|row|col|width;…`, NVS `wallRows`; empty = a master on its own).
- **Grid:** pure `ClusterLayout.h` — `{row,col,width}` validation (spans may not partially overlap; a row may have gaps, `col` is where a board hangs), wrap/align/slice into pre-positioned pieces a row shows verbatim. A row's text width is its flap count, never its physical reach; a literal `\n` forces the next grid row.
- **Wall state:** `WallState.cpp` — one leaf mutex, snapshot copies: rows table, per-row link facts and unit facts (a row's `/units/health` JSON read back into `UnitFacts` by `UnitFactsJson.h`; `tests/test_unit_facts_keys.py` gates its keys against the shared serializer), the job table (`WallOps.h`) with what each job handed back.
- **Unit jobs:** one call for the own row and a row board (`WallJobs.h`: names, values, wording; one job at a time per row). A row board's job is staged for the link task, written as `Op` when the row can take it and held open until its `OpState` ends it or time does (`WallLinkPolicy.h`: 20 s to hand over, 2 min a unit, 16 min for every unit); the own row's is a `DisplayCommand` whose result the worker reads off the display snapshot (`WallJobs.cpp`). A row board updating its units holds the producers back like the master's own unit update (`wallUnitUpdateRunning()`, sites gated by `tests/test_wall_jobs_glue.py`).
- **Row image by offer:** `WallUpdatePolicy.h` — a row on another rev than the stored image (`FollowerImageStore`, facts = rev, size, md5, packed) is sent `Update`, one row at a time; it downloads `GET /firmware/row` (`WebFirmware.cpp`, the file claimed for the connection's life) and answers `UpdateState`. Three failed offers block a row until a new image, another reported rev, ten minutes of health, a changed table or a master restart; an offer to a row in rescue mode costs its attempt when made.
- **Showing text:** producers (web drain, MQTT, the clock ticker) hand the wall's logical text to `WallShow.cpp`, which lays it out on the grid and gives every row its piece and its flip instant (`WallShowPolicy.h`: 400 ms lead, the clock's next minute 3 s ahead; each board flips 150 ms after the one before it in the table, #505); the own row goes through the DisplayCommand queue. Active only while the rows table has rows. Quiet and the row settings (tz, update units at start) go to every row at its Hello and on change.
- **Time:** the link task answers the rows' SNTP requests on UDP 123 (`SntpReply.h`), silent while the master's own clock is not synced.
- **Worker task:** everything that blocks on the network and may not run on the link task or netTask (`workerTaskMain` in `Tasks.cpp`): the pairing POST, the liveness probes, the end of an own-row job, the once-a-second look at the wall.
- **Pairing:** the web side stages, the worker (`WallPair.cpp`) posts `master=<id>` to the row's `POST /pair` and changes the table; a row the link has lost is posted the pairing again every 30 s (a master whose address moved).
- **Row image upload:** `POST /firmware/row?md5=` (`WebFirmware.cpp`; filename guard and cursor check pure in `FollowerImagePolicy.h`), accumulated in PSRAM and written by netTask.
- **Security:** trusted LAN — pairing and the link are not authenticated. What stays: a changing request (any method but GET/HEAD/OPTIONS) whose `Origin` is not this board's own LAN page is 403'd (`lanCsrfReject` in `shared/LanOrigin.h`, middleware in `WebEndpoints.cpp`; upload routes that write in `onUpload` gate INLINE at `index==0` via `webUploadCsrfRejected`), no route answers another origin, a row's address must be a plain private IPv4, `disable_auto_redirect` on the HTTP client, and upload gating is `shared/OtaUploadGate.h`.
- **Verdicts (#570):** pure `UnitVerdict.h` / `BoardVerdict.h` turn facts into a level (working / note / fault), the reason that leads with two numbers, and every reason that applies; a fault is something wrong now, history is a note. Reason numbers and names are fixed (new ones at the end). `WallWatch.cpp` is the only place that judges: once a second on the worker task, for the own row and every row board, published as a snapshot the API and MQTT copy.
- **Event record (#570):** 24-byte entries (time, board key, unit, kind, two numbers) in `/events.bin` → `/events.prev.bin` on the `storage` LittleFS, appended and rotated, never rewritten in place (`EventRecordPolicy.h`: format, the wait for the clock, paging; `EventRecord.cpp`: any task stages, netTask writes). What is recorded is `WallWatchPolicy.h`: a reason starting, a fault ending, a unit or row restart, with what a read could not speak for left as it was; job ends are recorded by `WallState.cpp`, the master's start by `main.cpp`, and what a row board says happened on it (`Event` on the link, names in `WallRowEvents.h`) by `WallLink.cpp`, dated back by the age the row gives and at most eight at once, then one per half minute, from any one row. Read by `GET /api/v2/history`.
- **API:** `WebWall.cpp` — `POST /api/v2/action`: jobs (`pair`, `release`, `arrange`, `update` = offer a row the stored image again, the unit jobs) → 202 `{op}`; what is done when accepted (`show`, `mode`, `quiet` — pure `WallActions.h`, staged as a `PendingSettingsPost` — `stop`, `restart` of the master or a row board, `forget-wifi`) → 200 `{done}`. `find-rows` is a job that only looks (mDNS `_splitflap._tcp`, run by netTask; pure `WallFind.h` holds every answer to a board's shapes; the list is the job's data, and a job without a number in `WallJobs.h` leaves no entry in the event record). A master on its own keeps no rows table: `GET /api/v2/wall` and the stream list its units as the one row. Every action and settings change goes through the gates in `WebEndpoints.cpp` (`webStagePost`, `webStageReboot`, `webStopWall`). A `show` for a time goes to every row. `GET /api/v2/op/<id>` (with a job's result data), `GET /api/v2/wall` (with the verdicts), `GET /api/v2/history`. Reads and settings are `WebBoard.cpp`: `GET /api/v2/board/<id>` and `/unit/<id>/<address>` (a unit's facts under readable names, pure `UnitApiJson.h`; `tests/test_unit_api_keys.py` ties every key of the shared facts serializer to its name), `/firmware`, `GET`/`PUT /api/v2/settings/wall` and `/settings/board/<id>` (pure `WallSettingsJson.h`, staged as a `PendingSettingsPost`), `GET /api/v2/log` (a row board's log is asked for over the link only while it is read: `RowLogPolicy.h`, `RowLog.cpp`, `setLogWanted` in the link core). The master is named by its own name in these paths. `GET /api/v2/stream` (`WebStream.cpp`, ticked by netTask; `StreamPolicy.h`: a topic is sent when its document changes). Strings from a snapshot go into a response through `jsonCopied()` (`JsonCopied.h`). A route with served routes below it is registered `AsyncURIMatcher::exact` (gate in `tests/test_api_index.py`).
- **The page (#574):** sources in `web/` — pure model (`web/model/`: wording of verdicts, wall layout, formatting; no DOM) and the app (`web/app/`: `dom.js` builds elements, text from a board only ever becomes a text node; one view a file). Written as ES modules; `web_bundle.py` joins `MODULES` (in import order) into one script inside `web/index.html` and generates `web/gen/constants.js` from the headers; `build_assets.py` embeds the document as `PAGE_HTML_GZ`, served at `/`. Tests: `tests/test_web_page.py` runs `node --test web/test/`, checks the bundle, the 40 KB gzip budget and that nothing parses a string as HTML. Preview without flashing: `python3 web/dev_server.py <master> [--read-only]` (page rebuilt per load, everything else passed to the master).
- **Bench:** `../link/fake_row.py` dials a master as a row does (`--pair-port` to be paired); `../link/fake_master.py` is the other end.

## Factory slot + custom bootloader

- **Factory slot (#193):** 2 MB `factory` app partition; bootloader factory reset (GPIO 4 low 5 s through reset) erases **otadata only** — never nvs (WiFi credentials must survive).
- **Custom bootloader (#201):** pioarduino ships the prebuilt stock bootloader and silently ignores bootloader-side `custom_sdkconfig` options — `firmware/v2/Bootloader/` (framework=espidf) builds ours; config + GPIO 4 constraints in its `sdkconfig.defaults`; artifact committed under `dist/` and swapped in at 0x0 by Master's `use_custom_bootloader.py` (build fails loudly if missing). Deployed boards get it once via `esptool write-flash 0x0`. Guarded by `tests/test_custom_bootloader.py`. `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE` stays in Master's AND Rescue's `custom_sdkconfig` — app-side load-bearing (esp_ota arms images as NEW). Deliberately excluded (eFuse burners): secure boot, flash encryption, anti-rollback.

Rescue app itself: `firmware/v2/Rescue/CLAUDE.md`.
- **Network liveness (#501):** restarts the board when traffic is dead behind a live WiFi link — rules in `NetLivenessPolicy.h`, probes on the worker task (`NetLiveness.cpp`), stepped in `WifiService.cpp`; glue pinned by `tests/test_net_liveness_glue.py`.
- **Quiet mode (#227):** no flap commands while set — rules in `QuietPolicy.h`, state in NVS + `tasksQuiet()`, HA switch `quiet`, told to every row board on the wall link; every content producer is pinned by `tests/test_quiet_glue.py`.
