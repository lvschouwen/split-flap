# v2 FollowerEsp01 (ESP-01 dumb row, #298)

Loaded when working in this tree; root CLAUDE.md holds build commands, workflow and Hard rules. Cluster wire contract and bench twins: `firmware/v2/Master/CLAUDE.md` (Cluster).

Minimal ESP8266 firmware (spec `2026-07-14-v2-esp01-follower-design.md`) turning v1 master hardware (ESP-01 + Nano row) into a cheap wall row under one S3 leader. Plain `.cpp` on the unified ESP32Async stack (#356: `esp32async/ESPAsyncWebServer` at the SAME exact version as Master/Rescue + `esp32async/ESPAsyncTCP` as its ESP8266 TCP side, `eagle.flash.1m.ld`); single-core superloop — **async handlers stage, `loop()` mutates and is the only I2C toucher** (`SERIAL_ENABLE` in `FollowerConfig.h` trades I2C for serial, shared pins `Wire.begin(1, 3)`).

- Endpoint surface is EXHAUSTIVE (spec table): `/cluster/{join,render,ping,leave,health}` (join/ping replies carry `plat:"esp01"` + `heap`/`rssi`/`up`), `POST /firmware/master?md5=` (ESP8266 Update flow; ota-flash.sh's rev compare is the revert detector), `/reflash-units` (one job per row: bundled hex through twiboot, one home, then the boot-section sweep — `shared/UnitUpdateJob.h`; progress in `/units/health`; `?address=N` = one unit as a `{"seq":N}` op, `&force=1` reflashes it even on the bundled rev and is refused without an address), tiny `GET /settings` + `POST /settings` (`reflashOnBoot` only), `/units/health(+refresh)`, the `{"seq":N}` op subset, `POST /reboot`. No HTML, no MQTT; `/cluster/{digest,promote,config,discover}` are NOT served by design (surfaced in `GET /api`'s `notServed` array, drift-gated by `tests/test_api_index.py`) — never a takeover candidate. Refused foreign-leader contacts are counted in `/cluster/health`'s `foreign` block (#358, `ClusterForeign.h` on both follower sides).
- Phases (the shared `ClusterMemberPhase.h` — the same machine an S3 member runs; `FollowerPolicy.h` only adds what this row does with it): Standalone → Clustered → Grace (holds last text) → LeaderLost = **blank** (~2 min silence); membership persists in EEPROM (`FollowerSettings.h`, magic `4FFS`) so a reboot lands in Grace. SNTP epoch-only for commitAt flips; unsynced = render immediately.
- **Clock fallback (#342):** the leader's POSIX tz rides the join (`tz=` additive) and persists with the membership; a Blank row with a held membership + synced time renders centered HH:MM (pure `FollowerClock.h`) instead of going dark. Leader content replaces it; leave drops the zone; no tz or no sync = blank as before.
- **Boot-rescue beacon (#343):** RTC-memory bad-boot counter (pure `FollowerRescue.h`, word offset 32; zeroed by 60 s uptime or the deliberate-reboot path — which OTA completion takes; a power cycle wipes it). 3 consecutive early deaths boot a minimal beacon: WiFi + cluster wire + OTA only, no I2C/probe/boot-home/render, unit ops 409, `rescue:1` in join/ping replies → the leader re-pushes the stored image.
- **Boot-reflash brake (#513):** `reflashOnBoot` (default true) gates BOTH boot passes — the early auto-install and the settled install + auto-update — so a gated campaign flashes nothing until asked (`commission-units.sh` requires it false). Persisted in a 3-byte prefs record directly behind the membership blob (`FollowerSettings.h`; an unreadable record decodes to the default, never to off) — the membership layout and magic are untouched, and a build predating the record drops it on its next membership write (back to true). Glue `FollowerPrefs.cpp` (handler stages, `loop()` writes, commits spaced 10 s, flushed before a restart). `?address=` on `/reflash-units` is decimal, query-only, and refused rather than ignored when malformed; the flash loop selects through `reflashShouldFlashUnit`. `tests/test_follower_boot_brake.py` pins the glue.
- **Reset history (#503):** each boot pushes the SDK reset info into a 4-entry RTC ring (pure `FollowerResetLog.h`, word offset 40, wiped by a power cycle) and logs it; served newest-first as `resets` in `/cluster/health` (`reason:exccause:epc1:excvaddr`). Log-ring lines carry an `[uptime s]` stamp.
- **WiFi join retry (#524):** `wifiInit()` gives the stored credentials `FOLLOWER_JOIN_ATTEMPTS` (3) join windows, in place, before the 5-minute setup portal; never `WiFi.disconnect()` between them (it can erase the SDK-persisted credentials). `tests/test_follower_join_retry.py` pins the loop.
- **WiFi TX power ladder (#508):** the shared `WifiTxPolicy.h` (same ladder as the S3, Master CLAUDE.md) run by `FollowerWifi.cpp` — stepped in the join loop, fixed for the portal, 1 Hz from `loop()`; an up-step polls the row for motion only when one is due. "Traffic confirmed" (#515) here = Clustered with a fresh leader contact (`followerLeaderContactFresh`), so a row the leader is talking to does not climb on a weak signal estimate. A firmware upload freezes the ladder and caps the level at the join ceiling. `txPower` in `GET /settings`. No level read-back exists on the ESP8266.
- Pure logic comes from `firmware/v2/shared/` (#408) — nothing to keep in sync. That includes the twiboot wire client (`TwibootFlash.h`, #526): `FollowerBus.cpp` supplies the `WireTwibootBus` adapter and the orchestration only (PROGMEM page fetch, `flashError` text from flash, batch settle). The op validators, the op / self-test result vocabulary and the reflash plan (incl. the consecutive-failure halt) are the shared `MaintenancePolicy.h` / `ReflashPlan.h` (#527); `FollowerOps.h` holds only the staged-op slot and the health buffer sizing. Op grading (`maintGrade*`), the self-test wait (`SelfTestPoll.h`: stale-terminal rule, unsupported after 3 unreadable polls, 45 s re-armed on RUNNING — the op result is stamped when the test ends, ok = passed, as on the S3), the in-place fact patches / read invalidation and the in-system twiboot update (`BootUpdateOp.h`, hooks in `FollowerBus.cpp`) are shared too (#529/#530). The reflash batch size is a build flag (`REFLASH_BATCH_SIZE=2` — bench-tuned, NOT the S3's 4). The LAN-origin / CSRF rule is the shared `LanOrigin.h` (#531); `FollowerCors.h` is only this board's CORS path allowlist. Tree-LOCAL trim that is deliberately NOT the shared version: this tree's reduced `ApiIndex.h`. **Unit bus (#534):** everything this row says to a unit is the shared `UnitBusCore.h` (frames, reads + validation, verified writes, the probe/poll reads, per-unit error ledger) and `UnitBusTwiboot.h` (rescue probe, boot-section read, unit flash), run on the `WireTwibootBus` adapter in `FollowerBus.cpp`; the flash loop is the shared `reflashRunTargets`, the boot dump `BootDumpOp.h`. `FollowerBus.cpp` keeps the adapter, the superloop scheduling, motion admission, bus-death recovery and log text (F() strings). Since the move this row also reads the drift diagnostics (`de/ds/dp/phys`), charges failed status reads and render writes to their unit (`err/errAge`), and counts `i2cTx/i2cErr` like the S3. Deliberately NOT here: the S3's per-unit transition log (`UnitEventLog.h` — a 4 KB log ring), a /stop abort of a flash, the S3's canary and phantom-ACK probe checks (ESP32 driver quirks). The member side of the cluster wire decides through the shared `ClusterWireGuards.h` (#533; row bound = `CLUSTER_MAX_MEMBERS`, `ClusterMemberAuth` holds the key + replay mark, join and ping replies carry one health-key block). `POST /firmware/master` decides through the shared `OtaUploadGate.h` (#532): hex-validated md5 before `Update.begin`, and 409 while a unit reflash is queued or running (the leader's rollout reads that as busy). Unit waits (probe inhibit, pre-probe delay, twiboot startup, return/home/stuck timeouts) are named once in `shared/UnitTimings.h` (#536). An op that invalidates a unit's reads (reboot-to-bootloader, boot dump, boot update) queues a probe — nothing else re-reads the offset here. `tests/test_shared_logic.py` (repo root) forbids re-implementing shared logic in a tree.
- `build_assets.py` bakes `data/unit-firmware.hex` (staged by `make_manifest.py stage`, CI-gated) into `UnitAssets.h` and stamps `follower-<rev>.bin` — the prefix ota-flash.sh keys the platform on. It also renders the whole `GET /api` reply from `ApiIndex.h`'s tables into `ApiIndexAsset.h` (PROGMEM); `tests/test_api_index_asset.py` compiles `buildApiJson()` on the host and requires the two to match byte for byte.
- **OTA image size (#540):** one app area of 1,028,096 B (`eagle.flash.1m.ld`) holds the running image AND the stored upload; eboot copies the upload down at reboot. A plain image must fit beside itself (ceiling 510,976 B); the build's `follower-<rev>-gz.bin` is the same image gzip-packed, which eboot unpacks, and moves the ceiling to ~600 KB at today's 70 % ratio. Every build prints both margins and fails when the image could no longer replace itself (`buildtools/fwbuild.py`, `ota_*`). The core cannot check a gzip upload, so `POST /firmware/master` does (pure `FollowerOtaImage.h`): the image header must be readable inside the file (the build leaves the first 16 bytes uncompressed — a plain `gzip` of the bin is refused) and carry the flash mode and size the board runs; the upload is stored at the top of the app area; and the unpacked image must end below its stored copy — eboot does not notice when it overwrites input it has not read. A plain upload takes the core's path unchanged. `GET /settings` reports `sketch`, `sketchFree`, `flashMode` and `flashId` (the flash chip — only the existing row's chip is proven for a packed flash; the core has open Puya/XMC reports). The packed image is the default OTA artifact (`ota-flash.sh` prefers it); the plain one is for USB provisioning and a row still on v1. `tests/test_ota_gzip_eboot.py` runs the installed core's own eboot copy routine on the host against the packed image.
- **RAM discipline (#519):** 82 KB total, ~44 KB static (the log ring is 4 KB of it). String literals live in RAM on this chip, and a `String`/`char*` body is copied again by the web library — so fixed replies are served from flash (`/api`), large replies are built in a buffer sized for the row and handed to a callback response (`/units/health`, `followerHealthBufCap`), and the log is streamed from the ring (`readSinceInto`). A throwing allocation resets this board on a miss, so a handler asks `heapCanHold()` before one and answers 503. No handler keeps a static buffer over 256 B (same pytest). The 1 KB boot-dump block is heap, claimed by the request that stages a dump and released by `loop()` before a reflash job or 5 min after its last write. A bus scan logs one line per unit that is NOT current (`FollowerScanLog.h`, the master's wording); a healthy scan stays one line.
- Tests: `pio test -e native` (policy/settings/json/ops/clock/rescue) + the fake_leader/fake_follower twin pytest (see Cluster bullet).
