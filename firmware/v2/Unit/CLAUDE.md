# v2 Unit (Arduino Nano)

Loaded when working in this tree; root CLAUDE.md holds build commands, workflow and Hard rules.

`Unit.ino` (config, globals, setup/loop) + siblings `UnitI2CProtocol.ino` (TWI ISRs + addressing) and `UnitMotion.ino` (stepper + hall calibration) — a one-TU concat model, main sketch placed first. I2C address: four DIP pins + `I2C_ADDRESS_BASE` (DIP 0000 → 0x01; 0x00 reserved for general call), or EEPROM-provisioned address with DIP fallback — twiboot still listens on the DIP-derived address, so over-I2C reflash requires EEPROM == DIP. 28BYJ-48 via ULN2003, KY-003 hall homing, per-unit EEPROM step offset clamped to ±`SFP_OFFSET_LIMIT_STEPS` on both protocol sides. Revolution odometer (#231): every drum move funnels through `stepCounted()`; ring policy pure in `UnitOdometer.h` (`pio test -e native` runs here too). EEPROM layout + block integrity pure in `UnitEeprom.h` (#406, day-0 — every block checksummed and every failure degrades to a safe default; the ring sits last so new scalars never move it, landing at `EE_RESERVED_NEXT_FREE`). The layout is **block-addressed, not version-addressed**: adding a field does NOT bump `UNIT_EE_LAYOUT_VERSION` (that means erase-everything and costs 21 hand-measured offsets), and a region earns its own version byte only when its repair is strictly cheaper than that full erase — `EE_RING_INIT_VERSION` (#417) is the one that qualifies. Lifetime health (what the unit remembers about its own decline across power cycles) reads back via `GET_LIFETIME` → `UnitLifetime.h`. **Feature gates (EEPROM byte 11, `UNIT_GATE_*`):** the two motion changes ship OFF so one fleet reflash can be proven incrementally; `SET_GATES` (0x99) / `POST /unit/gates` flips them over the wire on both row masters, verified by a `GET_LIFETIME` read-back, and the unit refuses bits it has no code for. Supply hold (#505, behind `UNIT_GATE_SUPPLY_WAIT`, pure `UnitSupplyWait.h`): before a letter move switches the coils on the unit reads its own rail, and more than 0.3 V under its own idle level (the once-a-second reading, followed slowly) it answers busy and asks again each loop pass, for 2 s at most; a move that was held says so in the ext-diag status byte (`heldForSupply` in the unit's facts). Idle hall consistency check (#268, behind `UNIT_GATE_IDLE_HALL_CHECK`): pure `UnitIdleHall.h` predicts the hall reading from the parked position and arms the existing #263 re-home on a debounced contradiction — coverage is partial by physics (see the header). **Failed home (#502, pure `UnitHomePolicy.h`):** a seek that never finds the marker drops `homed`, never steps on blind, answers `GET_LETTER` with `SFP_LETTER_UNKNOWN`, and owes a retry the unit pays by itself: it seeks again after 30 s, doubling per consecutive failure up to 16 min, then shows the commanded letter. `SFP_CMD_HOME` waits only the 30 s; the state is RAM only, so `SFP_CMD_REBOOT` clears it. A failed self-test has the same consequence; a passing one counts as a home. **Reset cause (pure `shared/UnitResetCause.h`, also what the masters decode):** the bootloader clears MCUSR and leaves the cause in GPIOR0; a reset the sketch asks for is a watchdog reset on the chip, so it stamps a checksummed EEPROM marker first (`markResetRequested()`, bytes 26–27) and only an unexplained one moves the lifetime watchdog counter — any new self-reset path must stamp it too. **Silence of the master (#584, pure `UnitBusSilence.h`):** a unit that was being addressed and then hears no frame for 3 min counts a silence, restarts its bus hardware (again every 3 min; no flap moves) and, behind `UNIT_GATE_SILENCE_RESTART`, restarts itself once after 20 min (it then finds home). A one-shot pin-change watch on SDA/SCL, armed only in a silence, says whether there was traffic for others. What it lived through is kept in EEPROM bytes 28–35 (written once it has lasted 6 min, at each doubling of the minutes after, and at its end; a shorter one costs no write) and read back by `GET_BUS_RECORD` → `shared/UnitBusRecord.h`: it survives the power cycle that usually ends a dead row. **Boot report refresh (#520, pure `shared/BootIntegrity.h`):** `loop()` rebuilds the cached `GET_BOOT_INFO` reply (boot-section CRC + state) every 10 min while the drum is parked, so the row masters' health poll sees a bootloader that rots after boot. The letter speed byte is clamped to `SFP_UNIT_SPEED_MAX`, the top of the masters' range. `tests/test_unit_motion_glue.py` pins the sketch call sites for all three. Calibration/provisioning driven from the master's web UI. Probe quirk: twiboot pinned alive by `isUnitInBootloader()` probe — the 1500 ms pre-probe delay is load-bearing.
